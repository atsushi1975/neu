# ノイ (Neu)

場の数字の合計が **101 を超えないように** カードを出し合うカードゲーム
「ノイ (Neu)」のオンライン対戦実装です。

フェーズ2と CPU 対戦まで完了しており、**Flask + 素の JavaScript** で
部屋作成 → 参加 → 開始 → 対戦 → 結果表示まで遊べます。
人間に加えて CPU を最大6人まで参加させられます（人間＋CPUで2〜7人）。
ルール判定は `neu/engine.py` に閉じており、UI / API 側では再実装していません。

## 必要なもの

- Python 3.10 以上
- Flask（`requirements.txt`）

## 起動

```bash
python3 -m pip install -r requirements.txt
python3 app.py --port 5001
```

ブラウザで `http://localhost:5001/` を開きます。スマホ縦画面を優先した UI です。

1. 名前を入れてルームを作成
2. 表示されたルーム ID を仲間に共有（または同じ画面のルーム一覧から参加）
3. 2〜7 人がそろったら、ホストが「ゲーム開始 ▾」から CPU 人数を選んで開始
   （人間だけで開始する場合は「CPUなしで開始」）
4. 手番になったら、手札のカードをタップするとその場で出る（即出し）
5. SHOT は、手札の SHOT をタップしてから、卓上の指名できる席をタップして出す
6. 出せるカードがすべて 101 を超えるとラウンド負け。チップが尽きると脱落し、最後の1人が勝者

ルールの要点:

- 合計が **101 を超える数字カードは出せない**。
- 手番の人が「次に出すカードがどれを出っても 101 を超える」状態なら、カードを出す前に
  その人のラウンド負け。チップが尽きると脱落し、最後の1人が勝者。
- 出したカードは場札の山（`table`）の一番上に積む。ゲーム開始時は全カードをシャッフルして
  3枚ずつ配るだけ（場札は空・合計0から始める）。ラウンドが終わってもカードを回収・
  配り直さず、場札は積み上がったままで合計だけ0に戻る。山札が尽きたときだけ場札をシャッフルする。

## 主な機能

- 部屋作成・参加・退出・ホスト引き継ぎ
- SSE によるリアルタイム更新
- 自分の手札だけを公開（他人の手札は枚数も中身も表示しない）
- 手番の人はカードをタップで即出す（2タップ確認・「出す」ボタン・アクションパネルは廃止）
- 出せるカードには「出すと合計 XX」（`afterSum`）バッジ、101 超え（`busts`）は赤い「超過」バッジを表示
- SHOT は円形卓の「指名できる席」だけが光って、タップで指名して出す
- 手番通知（プロンプト・ページタイトル・対応端末では振動）
- 場の合計は卓の中央に1か所、場札は一番上の1枚だけ、山札は裏面1枚＋残り枚数を表示
- 回る向きは「↻ 時計回り」「↺ 反時計回り」の文字1か所だけ（矢印の図形・回転アニメーションはなし）
- ラウンド敗者はサーバーの `lastRound.message` とチップ残り・脱落・次の最初の手番をトースト表示（手札は出さない）
- CPU が負けたトーストのタイトル、次が CPU のトースト本文、CPU の手番プロンプトに文字「CPU」のバッジを表示（人間だけなら従来どおり）
- ゲーム終了時は勝者と脱落順の順位を表示（1位=勝者、上位3人に 🥇🥈🥉）
- CPU の席のバッジ行と順位表の名前の横に、文字「CPU」のバッジを表示（「親」バッジと同形・色違い）
- カード画像が無い場合の CSS 仮カード表示
- CPU 対戦（開始時に人間＋CPUの合計が2〜7人になるよう選択）

## CPU 対戦

ロビーの「ゲーム開始 ▾」から、CPU を加えた合計人数を選んで開始できます。
CPU の表示名は `games/neu/__init__.py` の `CPU_NAMES`（ひらがなのよくある名前）から、
同じルーム内で重複しないようにランダムに選びます。人間の名前と同じ候補は
大文字小文字・前後の空白を無視して除外し、候補が足りない場合は `CPU1`, `CPU2`, ... に
フォールバックします。共通基盤の `GameDefinition.cpu_names` を指定しないゲームは、
従来どおり `CPU1`, `CPU2`, ... です。

CPU かどうかは名前ではなく id で判定します（`rooms.is_cpu_id`）。公開ビューの
`players[].isCpu` が真の席にだけ文字「CPU」のバッジを表示します。

- CPU も人間と同じ `legal_actions` / `apply` を通してカードを出します。
  CPU 専用のルール判定はありません。
- 出せるカードの選び方（`legal_actions` の合法手のみ、次の順で判定）:
  1. 101 ぴったり狙い: 出せる赤数字で場の合計がちょうど 101 になるものがあれば 90% でそれを出す（n101 は除外）。
  2. 特殊 101 の奇襲: 場の合計が 50 以下かつ手札に n101 と n101 以外の黒カードがあるとき、90% で n101 を出す。
  3. 通常判定:
     - 赤数字のみ: 90% で最大の赤数字、10% でランダム。
     - 黒カードのみ: 80% で優先度順（`pass` ＞ `turn` ＞ `shot` ＞ `nm1` ＞ `n101` ＞ `nm10` ＞ `double`）の最優先、20% でランダム。
     - 混在: 80% で最大の赤数字、20% で黒カード（その中 80% で優先度最優先、20% でランダム）。
- 赤数字は `n1`〜`n9`, `n10`, `n50` です。
- SHOT の指名先は、各人が直近5枚に出したカードのうち赤数字だった比率に比例する確率で選びます。
  全員 0 なら均等ランダムです。
- CPU は1手ごとに 1.5 秒待ってから打ちます（犯人は踊ると同じ方式・値）。
  人間の手番では CPU は動きません。
- CPU の乱数は CPU 自身の `random.Random` で、テストでは seed を固定できます。

## 退出システム（承認制）

進行中のゲームを途中で抜けるには、他の全員の許可が必要です。
ヘッダの「退出」ボタンから申請すると、他のプレイヤーに「許可 / 拒否」の帯が表示されます。
全員が許可するとゲームは中止され、全員がロビーに戻ります。
拒否または 30 秒の時間切れで却下され、申請者は 120 秒再申請できません（取り消しはクールダウンなし）。
ゲーム終了後は承認なしで即退出できます。

## 手動確認の手順（テストプレイ後 UI 改善）

- 2〜7 人それぞれで円形卓が崩れないこと（席が重ならない・卓の枠からはみ出さない）
- TURN で「↻ 時計回り」「↺ 反時計回り」の文字が切り替わること
- SHOT の指名（SHOT をタップした直後の席タップでも成功すること）
- 即出し
- DOUBLE 中のグレーアウト
- 出せないカードのグレーアウトと「超過」バッジ
- 場札が一番上の1枚だけ表示されること（重なり・傾きなし）
- 場の合計が卓の中央1か所だけに表示され、プレイ後に更新されること
- ラウンド結果トーストに手札が出ないこと
- CPU が負けたトーストのタイトル・次が CPU の本文・CPU の手番プロンプトに「CPU」バッジが出ること
- 人間だけの対戦ではトーストに CPU バッジが出ないこと
- CPU の席（バッジ行）と終了画面の順位表に文字「CPU」のバッジが表示されること（7人戦でもはみ出さない）
- 席が「名前 / バッジ行 / チップ」の3段で、バッジが無い席もバッジ行の高さが同じこと
- 「親」が移動しても席の大きさ・位置が変わらないこと
- 短い名前が省略されず、16文字の名前でも席からはみ出さないこと
- スマホ幅（390×844 / 360×640）でスクロールなしで収まること

円形卓の座標計算は `static/table-layout.js` の純粋関数として node でテスト済み（`node static/table-layout.test.js`）。
